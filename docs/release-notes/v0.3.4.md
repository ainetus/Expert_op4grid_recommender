# v0.3.4 — Evacuation antennas: detection, drawing and levers

A minor release on top of `0.3.3.post3`, with no breaking API change.

**Evacuation antennas** become a structural element of the overflow graph and a
recommendation lever, on by default (#129). The release also carries two
overflow-graph fixes: the DC graph's flow transfer (#128) and the injection
colours of the nodes on the pypowsybl backend.

Default recommendations change only where an evacuation antenna exists: its
units become curtailment / redispatch candidates. Set
`EVACUATION_ANTENNA_LEVERS=False` to get the 0.3.3 families back.

## Highlights

- **Evacuation antennas.** An evacuation antenna is a part of the grid tied to
  the constrained path through a single node (or several, when it is
  insensitive) whose net production leaves through that node. Its report is ~0,
  so its branches are gray: it was invisible to the structured graph, to the
  reduced drawing and to the injection levers. Design and plan:
  `docs/recommender/evacuation_antennas.md`.
  - **Detection** (`graph_analysis/structural_antennas.py`): both sides of the
    constrained path, typed `evacuation`, `evacuation_downstream`,
    `consumption_upstream` or `consumption`. It costs about 80 ms per analysis
    on the full French grid.
  - **In the analysis**: the antennas are tagged on the overflow graph
    (`antenna_id`, `antenna_type`, `in_evacuation_antenna`,
    `is_antenna_attachment`) and returned as
    `AnalysisResult.structural_antennas`. Settings: `ENABLE_STRUCTURAL_ANTENNAS`
    (on), `STRUCTURAL_ANTENNA_MIN_MW`, `STRUCTURAL_ANTENNA_MAX_FRACTION`.
  - **Drawing**, through expertop4grid 0.3.4: the reduced overflow graph keeps
    the evacuation antennas, in ochre with their report, and the interactive
    viewer gains an *Evacuation antennas* layer.
  - **Levers** (`EVACUATION_ANTENNA_LEVERS`, **on by default**):
    - upstream antennas are lowered: curtailment for renewables, lowering
      redispatch for dispatchable units;
    - downstream antennas are only raised: redispatch up within the Pmax
      headroom, never curtailment;
    - a unit reaches the constrained path through the antenna's attachment node
      with the largest influence;
    - each antenna also gets one MW-sized pro-rata option (`curtail_<id>`,
      `redispatch_<id>`) acting on the setpoints (`gen_target_p`, `gen_pmax`
      added to `PypowsyblObservation`).
- **Real case.** Vendée full-France snapshot, contingency `MERLAL62SOULL`,
  overload on `PALLUL41ZGARA`. The detection finds the Vent des Îles offshore
  park: units V.ILEEG1 and V.ILEEG2, 231 MW exported through the Soullans
  transformers.
  - With the levers off, no recommended action solves the overload: the best one
    leaves it at ρ 1.03.
  - With the levers on, curtailing one of the two units (half the park, the
    operator's actual parade) solves it, with a post-action max ρ of 0.91.
  - The MW-sized aggregate (−18 MW) stops just short, at ρ 1.03.
  - The analysis takes about 3 s more (41 s instead of 38 s).
- **DC overflow graph (`USE_DC_FOR_OVERFLOW_GRAPH`) measures a DC flow
  transfer** (#128).
  - The opt-in DC graph used to compare DC post-cut flows to the AC N-1 base,
    so every branch also carried the AC/DC gap. On full-France snapshots that
    meant 1,100 to 1,250 spurious coloured edges, and a distorted constrained
    path on one case.
  - It now solves the N-1 state in DC before and after the cut and applies that
    transfer on the AC base, for one more DC load flow (about 0.3 s on France).
- **Node injections of the overflow graph (pypowsybl backend).**
  - No node was ever drawn as a production node, and consumption values sat on
    the wrong nodes: alphaDeesp reads one value per flagged substation, not a
    full array.
  - `alphadeesp_node_injections` builds the right shape from the N-1
    observation, production counted positive. Only node attributes change.
- The islanded-pocket `antenna_meta` now reports the pocket's production on
  pypowsybl, through the new backend-agnostic injection helpers
  (`utils/injections.py`).

## Compatibility

- **Default recommendations change where an evacuation antenna exists**, since
  the levers are on by default. `EVACUATION_ANTENNA_LEVERS=False` restores the
  0.3.3 families. With the levers off, the detection alone leaves the
  prioritized actions and scores unchanged; an end-to-end test guards this.
- **Dependency floor `expertop4grid>=0.3.4`** (`requirements.txt` pins 0.3.4).
  - With an older expertop4grid the antennas are still detected, typed and used
    as levers, but not drawn.
  - When upgrading an environment where pandapower caps numpy, `pip install
    --no-deps -U expertop4grid==0.3.4` avoids a numpy downgrade.
- **New payload key** `structural_antennas`, and new action ids
  `curtail_<antenna_id>` / `redispatch_<antenna_id>` (multi-generator
  `set_gen_p`). Downstream consumers must forward and display them;
  Co-Study4Grid's NDJSON `result` event selects result keys one by one.
- The DC graph mode (`USE_DC_FOR_OVERFLOW_GRAPH`, opt-in) now builds a
  different, correct graph.
